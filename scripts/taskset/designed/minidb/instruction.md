# minidb 规格

在当前目录从零实现一个小型关系数据库：按下面的 SQL 子集建表、增删改查，数据存在磁盘上，进程被杀掉也不损坏。只用 Python 3 标准库，不安装任何包；**不得使用 `sqlite3`、`dbm`、`shelve` 模块**。包名 `minidb`，命令为：

```
python3 -m minidb <数据库目录> [SQL]
```

数据库目录不存在时创建。给了 `SQL` 参数就执行它，否则从标准输入读入全部 SQL 再执行。

## 1. 执行与输出

- SQL 文本由分号分开的若干语句组成（字符串里的分号不算），最后一条后面的分号可省略；空语句忽略。语句按顺序执行。
- `SELECT` 的输出：第一行是列名，之后每行一条结果；同一行的值用 `|` 连接。值的写法：`NULL`；整数写十进制；实数按 Python 的 `repr(float)`（如 `2.0`、`0.1`、`1e+20`）；文本原样。
- `INSERT`、`UPDATE`、`DELETE` 各打印一行 `inserted <N>`、`updated <N>`、`deleted <N>`（N 为受影响的行数）；其他语句不打印。
- 错误：在 stderr 写一行以 `error:` 开头的说明，退出码 1，**不再执行后面的语句**。出错的语句没有任何效果；在显式事务中出错时，整个事务回滚。没有错误时退出码 0。

## 2. 词法

- 关键字与标识符不区分大小写。标识符为 `[A-Za-z_][A-Za-z0-9_]*`，不能是关键字。
- 字符串字面量用单引号，`''` 表示一个单引号。数字：`[0-9]+` 是整数，`[0-9]+\.[0-9]+` 是实数；负数由一元负号得到。`NULL` 是空值。
- `--` 到行尾是注释。

## 3. 类型与约束

- 列类型：`INTEGER`、`REAL`、`TEXT`。存入的值必须是 NULL 或与列类型相符：`INTEGER` 列只收整数；`REAL` 列收实数或整数（整数转成实数存）；`TEXT` 列只收文本。不符是错误。整数没有大小限制。
- 列约束（可组合）：`PRIMARY KEY`（每表至多一列，隐含 `NOT NULL` 与 `UNIQUE`）、`NOT NULL`、`UNIQUE`（多个 NULL 不算重复）、`DEFAULT <字面量>`（可以是负数）。违反约束是错误。

## 4. 语句

- `CREATE TABLE [IF NOT EXISTS] <表> (<列> <类型> [约束...], ...)`：表已存在时，没有 `IF NOT EXISTS` 是错误，有则什么也不做。列名在表内不得重复。
- `DROP TABLE [IF EXISTS] <表>`：同时删除它的索引。
- `ALTER TABLE <表> ADD COLUMN <列定义>`：已有行的新列取默认值（没有则 NULL）；`NOT NULL` 而没有默认值，或 `PRIMARY KEY`、`UNIQUE`，是错误。
- `CREATE INDEX <索引名> ON <表> (<列>)`、`DROP INDEX <索引名>`：索引名全库唯一。索引不改变任何结果，只影响速度（第 7 节）。
- `INSERT INTO <表> [(<列>, ...)] VALUES (<表达式>, ...), (...)`：给了列清单时，没列出的列取默认值或 NULL；没给时按建表顺序给出全部列。值的个数不符是错误。一条语句的所有行要么全部插入，要么（出错时）一行也不插入。值里的表达式不能引用列。
- `UPDATE <表> SET <列> = <表达式>, ... [WHERE <条件>]`：右边的表达式按更新前的行求值。所有行更新后再检查约束。
- `DELETE FROM <表> [WHERE <条件>]`。
- `BEGIN`、`COMMIT`、`ROLLBACK`：显式事务。事务外每条语句自动提交。事务中再 `BEGIN`、事务外 `COMMIT` 或 `ROLLBACK` 是错误。脚本结束时仍在事务中，则回滚。
- `SELECT`：

```
SELECT [DISTINCT] <列项>, ...
  [FROM <表> [[AS] <别名>] {[LEFT] JOIN <表> [[AS] <别名>] ON <条件>}]
  [WHERE <条件>] [GROUP BY <表达式>, ...] [HAVING <条件>]
  [ORDER BY <表达式> [ASC|DESC], ...] [LIMIT <整数> [OFFSET <整数>]]
```

  - 列项：`*`（FROM 中所有表的全部列，按表的出现顺序与建表顺序）、`<表或别名>.*`、`<表达式> [AS <别名>]`。
  - 列名（输出的第一行）：直接引用的列用它在 `CREATE TABLE`（或 `ADD COLUMN`）中写的名字；有 `AS` 用别名；其余为 `expr<k>`，k 是这一项在列项中的序号（从 1 起，`*` 展开前计）。
  - 没有 FROM 时只有一行（如 `SELECT 1 + 2`）。
  - 求值顺序：FROM 与 JOIN（`JOIN` 为内连接，`LEFT JOIN` 对左边没有匹配的行补一行右表全为 NULL）→ WHERE → GROUP BY 与聚合 → HAVING → 列项 → DISTINCT → ORDER BY → LIMIT/OFFSET。
  - 有 GROUP BY，或列项、HAVING 里有聚合函数时做分组（没有 GROUP BY 时整个结果是一组，输入为空也输出一行）。分组后，列项、HAVING 与 ORDER BY 中出现在聚合函数之外的列，必须出现在 GROUP BY 中，否则是错误。GROUP BY 与 DISTINCT 把 NULL 看作彼此相等。
  - ORDER BY 的表达式可以是列项的别名，或整数 k（第 k 个输出列）。排序规则：NULL 最小，其次数值（整数与实数按数值比较），最后文本（按码点）；`DESC` 反过来（NULL 最大）。排序键都相等的行之间顺序不限；没有 ORDER BY 时行的顺序不限。
  - LIMIT 与 OFFSET 为非负整数。

## 5. 表达式

优先级从低到高：`OR`；`AND`；`NOT`；比较（`= != <> < <= > >=`、`IS [NOT] NULL`、`[NOT] LIKE`、`[NOT] IN (...)`、`[NOT] BETWEEN ... AND ...`）；`+ - ||`；`* / %`；一元负号。同级左结合；括号改变顺序。另有 `CASE WHEN <条件> THEN <表达式> ... [ELSE <表达式>] END`。

- **列引用**：`列` 或 `表或别名.列`。找不到是错误；不带前缀而几张表都有这一列是错误。
- **算术**：任一边是 NULL 结果为 NULL；文本参与算术是错误。两边都是整数，结果是整数（`/` 向零截断，`%` 的符号与被除数相同）；否则结果是实数。除数为 0 时结果为 NULL。
- `||`：任一边 NULL 则为 NULL；否则两边都按第 1 节的写法转成文本后连接。
- **比较**：任一边 NULL 结果为 NULL；整数与实数按数值比较；文本之间按码点比较；数值与文本比较是错误。结果为整数 1 或 0。
- **真假**：条件的值为 NULL 时既不真也不假（三值逻辑：`NOT NULL` 为 NULL；`AND` 有一边假则假，否则有 NULL 则为 NULL；`OR` 有一边真则真，否则有 NULL 则为 NULL）。数值非 0 为真、0 为假；文本作条件是错误。WHERE、ON、HAVING 只保留条件为真的行。
- `IS NULL`、`IS NOT NULL`：结果总是 1 或 0。
- `LIKE`：两边必须是文本（否则错误，NULL 除外）；`%` 匹配任意串，`_` 匹配一个字符，ASCII 字母不区分大小写。
- `x IN (a, b, ...)`：有一项等于 x 则为 1；否则 x 为 NULL 或列表中有 NULL 则为 NULL；否则为 0。`NOT IN` 取反（NULL 仍为 NULL）。
- `x BETWEEN a AND b` 等同 `x >= a AND x <= b`。
- `CASE`：取第一个条件为真的 THEN；都不真取 ELSE，没有 ELSE 为 NULL。
- **函数**（参数为 NULL 时结果为 NULL，`COALESCE` 除外；类型不对是错误）：`LENGTH(文本)` 字符数；`UPPER`、`LOWER`（只改 ASCII 字母）；`ABS(数值)`；`ROUND(数值[, 位数])` 四舍五入（.5 远离 0），结果为实数；`SUBSTR(文本, 起点[, 长度])`，起点从 1 起，超出范围取空串；`COALESCE(x, y, ...)` 第一个非 NULL 的参数，都为 NULL 则为 NULL。
- **聚合**：`COUNT(*)`；`COUNT([DISTINCT] 表达式)`、`SUM`、`AVG`、`MIN`、`MAX` 忽略 NULL。`COUNT` 为整数；`SUM` 在全是整数时为整数，否则为实数，没有非 NULL 值时为 NULL；`AVG` 为实数，没有值时为 NULL；`MIN`、`MAX` 按比较规则，没有值时为 NULL。聚合函数不能嵌套，也不能出现在 WHERE、ON、GROUP BY 中。

## 6. 存储与可靠性

- 全部数据存在数据库目录里，格式自定。命令成功返回后，结果在下次打开时可见。
- **原子与持久**（只考虑进程被杀，不考虑断电）：进程在任何时刻被 `kill -9`，再打开数据库时，看到的恰好是最后一次已提交的状态——自动提交的语句要么完全生效要么完全没有，显式事务要么全部生效要么全部没有，不会出现半条语句或损坏。
- 两个进程同时写同一个数据库：两边都成功，结果与按某个先后顺序执行相同。

## 7. 性能

在 2 个 CPU 的机器上：

- 一个脚本里 5000 条单行 `INSERT`（每条自动提交）在 20 秒内执行完。
- 有 10 万行的表上，对建了索引的列做等值查询（`WHERE <列> = <值>`）的单个命令在 1 秒内返回（含进程启动与打开数据库）。
- 10 万行的表上 `SELECT COUNT(*) ... WHERE` 全表扫描在 5 秒内返回。
