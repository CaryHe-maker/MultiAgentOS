> 2026-11-07。接口 `POST https://api.deepseek.com/v1/tools/search` 与 `/v1/tools/fetch`，规格以 <https://api-docs.deepseek.com/guides/search> 及其 `api/search`、`api/fetch` 两页为准（已读，字段、状态码、价格与 M2TechStack 第 3.3 节的描述一致）。脚本 `apps/control-plane/test/acceptance/web-eval/run-web-eval.ts`，共 107 次请求；原始记录与汇总在 `apps/control-plane/test/acceptance/web-eval/results/2026-11-07/`（只含请求、状态码、耗时与结果摘要，不含密钥）。**这是单次实测，不是统计结论。**

## 1. 结果

| 实验 | 结果 | 与通过标准比 |
|---|---|---|
| W-T1 协议 | 401（错误 key）、400（query 超过 128、`count` 超过 50、`file://`）、404（不存在的页面）、403（`127.0.0.1`、`10.0.0.1`、`169.254.169.254`）都与文档一致，私网地址不返回正文；多余的请求字段被忽略（200）。**一处与预期不同**：无意义的乱码查询返回了 10 条结果而不是空数组（搜索是语义检索，几乎不会为空），所以"空结果为 `results: []`"在这里无法观察 | 通过；空结果一项无法验证 |
| W-T2 搜索质量 | 16 个有明确答案的查询（中文与英文、报错信息、官方文档、版本号）前 3 条都含相关结果，16/16；`site:` 与 `after:` 算符 4/4 有效；`rerank_score` 10/50/90 分位为 1.70 / 1.98 / 2.26（区分度不大，几乎都在"高质量"一侧） | 通过（标准 ≥80%） |
| W-T3 抓取 | 静态文档站 4/4、GitHub README 2/2、源码 1/1、raw 1/1、issue 页面成功（我的判据误判为失败，正文是对的）、中文 2/2、多次重定向 2/2。**失败**：PDF 404；`reddit.com` 404（站点策略）；`wikipedia` 的长列表页 200 但只有 1337 字节（链接列表被整段丢掉）；不存在的页面 404（符合预期） | 静态与 GitHub 类别通过；其余如实记录 |
| W-T3 内容质量 | 标题保留；**代码块没有围栏**（`fences=0`，代码以缩进或普通行出现）；**链接基本丢失**（MDN 页面 0 个链接，Node 文档 189 KB 中 5 个）；**行内代码与相邻文字粘连**（"Themap() method"）；GitHub 页面带"Skip to content"等导航文字 | 可读，但对 Agent 有损：不能顺着链接走，代码边界要靠上下文猜 |
| W-T4 时延与限流 | 搜索 p50 435 ms、p95 521 ms；抓取串行 p50 267 ms、p95 3.4 s，但 **GitHub 页面每次约 10.8 s**；30 个并发抓取 27 个成功、3 个 429（未测 `Retry-After`） | 搜索通过；抓取除 GitHub 外通过 |
| W-T5 计费 | **无法验证**：`/user/balance` 在这个账户上前后都读到 0，107 次调用都成功，没有扣费可见（可能是赠送额度或余额接口不反映） | 未通过也未失败，需要有余额的账户重测 |
| W-T6 内容安全 | 取含"忽略之前的指示"原句的页面（OWASP Prompt Injection）：正文原样出现，接口没有改写或过滤（第一个候选页没有这句话，只作废） | 通过；"封装标为不可信"是我们的实现，由 `stage6-exit` 测 |
| W-T7 本地对照 | 最小的本地实现（HTTP 取回、去标签、标题转换）20 个地址成功 17 个，DeepSeek 15 个；本地多成功 GitHub issue 与长列表页，PDF 与 reddit 同样失败；本地版没有链接与代码围栏，质量不高于 DeepSeek | 两者成功率接近 |

## 2. 没有写明、也没有测到的

- 是否渲染 JavaScript：`angular.dev` 抓到了正文，`reddit.com` 没有（404），不能下结论。
- 是否遵守 robots.txt：文档只说"站点策略"可能导致 404，没有证据。
- 搜索词与 URL 的留存与隐私：文档没有说明，**不能由实验得出**；`M2Security` 里按"数据发给 DeepSeek"处理。
- 计费：见上。
- 429 的 `Retry-After`：3 次 429 没有核对响应头。

## 3. 对提供方的结论（待 Cary 决定）

按 M2TechStack 第 3.3 节的结论表，这次落在第二行：**搜索通过，抓取覆盖静态页面与 GitHub，其余类别有缺口**。

- **搜索**：DeepSeek 作为默认提供方，质量与时延都明显达标，算符可用；Tavily 不需要。经 `SearchProvider` 端口，以后可以换。
- **抓取**：DeepSeek 作为首选，**保留本地抓取作为回退**（失败时、或页面是它抓不好的类别时），因为 W-T7 显示两者互补（本地多成功长列表页与 issue 页，PDF 和 reddit 两边都不行），而且 DeepSeek 的 Markdown 丢链接、丢围栏。本地抓取要做的是地址检查、重定向逐跳检查、大小上限和结果封装，这些无论哪个提供方都要做。
- **未决**：计费与隐私没有证据。建议隐私按最坏情况写进 M2Security（搜索词与抓取地址会发给 DeepSeek，且每次都经授权询问与审计），计费用有余额的账户补测一次，不阻塞实现。
