# M1 限制清单

本文列出 M1 发布版本的已知限制：哪些情况 M1 不处理、处理得不完整，或依赖使用者自己注意。
范围以 [M1Plan](M1Plan.md) 为准，第 3 节的非目标不在这里重复解释，只在第 1 节列出名称。
每条限制都是有意的取舍或明确的边界，触发时系统给出结构化的拒绝或说明，而不是静默出错。

## 1. 不提供的能力（M1Plan 第 3 节）

文件写入、项目命令、项目测试、任何 git 调用、Coding Agent、多 Task/DAG、并行 Agent、动态重规划、崩溃续跑、
暂停/恢复、持久审批、AgentRun 级额度、Checkpoint/Restore、Web UI、多租户、远程执行、跨进程 IPC、消息集群、
语义向量检索与生产级隔离。相关请求返回结构化的 Unsupported 结果。

## 2. 运行环境

| 限制 | 说明 |
|---|---|
| 平台 | 验收与 CI 兼容矩阵只覆盖 Ubuntu 24.04 LTS（M1TechStack 第 11 节）。Windows 与 macOS 可用于开发，但不在验收范围内；Windows 上创建符号链接需要额外权限，相关测试会失败 |
| Node.js | 只支持 `>=24.19.0 <25` |
| ripgrep | 有 `rg` 时用它检索，否则用内置扫描；两者结果一致，内置扫描在大仓库上更慢 |
| 运行形态 | 单进程、单用户、单项目、同一时间只有一个运行；运行状态不持久化，进程退出后不能恢复或续跑 |

## 3. 模型服务商

| 限制 | 说明 |
|---|---|
| 服务商 | 只接入 DeepSeek（OpenAI 兼容协议）。默认模型 `deepseek-flash@v1.0.0`；`deepseek-v4-pro@v1.0.0` 已定义但未经验收评测 |
| 思考模式 | 两个 Agent 都关闭思考模式；DeepSeek 在思考模式下不支持强制工具选择，收尾调用依赖强制选择 |
| 强制工具选择 | DeepSeek 不保证遵守强制工具选择。收尾调用回复了其他工具或不合法的 JSON 时，系统按已知用量技术重试（最多 3 次，ExecutorSet 4.5）；重试都失败时生成降级报告 |
| 计价 | 成本按定义文件中 2026-09-28 公布的价格计算；DeepSeek 调价后需要发布新的 Model 定义版本。中国法定节假日按非高峰计费，M1 没有节假日日历，按规则算出的节假日成本是上限 |
| 网络 | 需要能访问 `https://api.deepseek.com`；服务商不可达或限流时按 ExecutorSet 4.5 的表格重试或失败 |

## 4. 仓库与文件

| 限制 | 说明 |
|---|---|
| 只读 | 只能读取用户在开始时授权的仓库；不能写入、执行命令或调用 git，仓库版本以快照摘要 `snapshotId` 标识 |
| 默认排除 | `.git`、`.env*`、`*.pem`、`*.key`、`id_rsa*` 等私钥文件与 `node_modules` 不可读取，也不进入概览与检索；可在配置中追加排除规则（`kernel.repositoryExclusions`），不能删除默认规则 |
| 秘密保护 | 只依靠路径排除规则。写在普通源码或配置文件中的密钥不会被识别或遮蔽，会随读取内容发给模型服务商 |
| 文件数量 | 排除之后超过 `maxSnapshotFiles`（默认 20000）个文件的仓库无法建立快照，运行以失败结束；可在配置中调大 |
| 文件大小 | 超过 16 MiB 的文件不可读取；单次读取最多 400 行，且不超过 16 KiB |
| 文本编码 | 只读取 UTF-8 文本。GBK 等其他编码的文件与二进制文件一样不进入概览与检索，读取时返回 `UNSUPPORTED_FILE` |
| 符号链接 | 不跟随符号链接；指向仓库外的路径被拒绝 |
| 检索 | 文本、路径与正则式的符号检索，不做语法分析、语义向量检索或跨会话记忆（M1TechStack 第 8 节）；符号检索可能漏掉不规则的写法 |

## 5. 分析能力与预算

| 限制 | 说明 |
|---|---|
| Agent 结构 | 固定为 Planner 交接给 CodeViewer 一次；Planner 最多 3 轮，CodeViewer 最多 20 轮，每轮最多 8 个工具调用 |
| 单次运行额度 | 300000 token（按固定任务集校准，Monitor 第 4 节）。最坏情况下单次约 0.36 美元；固定任务集实测平均约 0.006 美元。额度或轮数将尽时进入收尾，CodeViewer 必须基于已读内容作答 |
| 运行时长 | 运行超时 30 分钟；授权询问 5 分钟内未回答视为拒绝，运行以失败结束 |
| 报告 | 结论只认 `read_file` 读过的行；没有读取依据的结论列为“未查证的问题”。报告最大 256 KiB |
| 来源核验粒度 | 一条结论只要有一个来源没被读取过（例如模型顺带引用了只在检索结果里见过的 README 或 `package.json`），整条结论就降为未查证，即使其余来源都已读过。固定任务集中 F4 偶尔因此缺少预期来源（R5.7 评测：Prompt 约束不能稳定消除）。根本解决是发现未读来源时退回模型补读或删去该来源，需要修改 Workflow 与协议，留到 M1 之后 |
| 评测基线 | 成功率、来源完整性、成本与延迟基线只在固定的小型 fixture `bookshelf` 上取得（M1AcceptanceEvidence 第 7 节）；更大仓库上的表现未测 |
| 定义版本 | Agent、Unit、Tool、Prompt 已封存（当前入口为 `planner@v1.1.0`）；修改提示词或工具说明必须发布新版本，不能编辑已封存的文件 |

## 6. 开发流程

| 限制 | 说明 |
|---|---|
| CI 触发 | `pull_request` 只匹配 `main` 与 `feat/**`；`feature/M1/main` 上的提交靠 push 触发（D6） |
| 协议冻结 | M1 协议已冻结（M1Interface 1.2）：同一 major 只能增加语义明确的可选字段或独立 Schema，破坏性变更必须创建新 major；协议快照守卫在 CI 中强制 |
