# MultiAgentOS M2 安全

> 状态：已评审（阶段 1、2 的部分）；阶段 3 的第 3b 节为草稿，待评审。

## 1. 目的与范围

本文集中说明 M2 的威胁模型、各类风险由哪一层防护，以及验收 C5 的拦截矩阵。机制分散在各组件文档中，本文只做汇总与对应，
不重新定义机制；设计以 [M2Design](M2Design.md) 第 5、6、9.5、9.6 节为准。

## 2. 威胁模型（框架）

| 来源 | 假设 | 阶段 |
|---|---|---|
| 被分析仓库的内容（源码、文档、`AGENTS.md`、模板） | 可能来自他人，可能包含提示注入；不获得指令权威，除非用户按内容信任过 | 1 |
| 模型输出 | 只是提案；可能编造工具、越权、重复调用 | 1 |
| 网页内容 | 不可信；可能包含提示注入与指向内网的地址 | 6 |
| 命令 | 在沙盒中运行；可能试图联网、越出可写范围、读取凭据 | 3 |
| 用户 | 可信；但可能被诱导批准，因此授权询问只展示实际要执行的内容 | 1 |

## 3. 项目指令的信任（阶段 1）

| 风险 | 防护 | 位置 |
|---|---|---|
| 克隆来的仓库借 `AGENTS.md` 取得 system 级的指令权威 | `AGENTS.md` 一律不进入 system 段；只有用户按 `(仓库, SHA)` 确认信任过的内容才标明为项目指令；内容一变化就重新询问 | [Kernel/Core](Kernel/Core.md) 第 5.2 节 |
| 未被信任的 `AGENTS.md` 仍可能包含注入 | 以 user 角色、标明"仓库材料，未经用户信任"追加在历史末尾 | [ExecutorSet](Library/ExecutorSet.md) 第 6.1 节 |
| `readonly` 预设下被诱导信任 | `readonly` 预设不询问，`AGENTS.md` 一律按未被信任处理 | Core 第 5.2 节 |
| 信任记录被当作授权 | 信任记录不授予任何执行能力，不是授权条目，也不是 Lease | M2Design 第 9.5 节 |
| Agent 修改 `AGENTS.md` | 只能经文件工具，按极危险级逐次询问；命令无法写入或新建（阶段 2、3）；根目录与子目录相同 | M2Design 第 5.2、6.1 节 |
| 子目录的 `AGENTS.md` 借"项目指令"取得权威（阶段 2） | 信任规则与根目录相同，按 `(仓库, 相对路径, SHA)` 确认；被信任的也只以 user 角色、标明已信任的条目追加；未被信任的标明为仓库材料；每个投影至多 8 份 | M2Design 第 9.5 节 |

## 3a. 写入范围与受保护路径（阶段 2）

文件工具在进程内运行，防线是代码，不是操作系统（M2Design 第 2.5、6.3 节）。

| 风险 | 防护 | 位置 |
|---|---|---|
| 写到仓库之外 | 路径规范化；逐段检查符号链接；写入后校验 realpath | [ExecutorSet](Library/ExecutorSet.md) 第 5b 节 |
| 改动 `.git/`、`.multiagentos/` | `isWritable` 返回 `PROTECTED_PATH`，不询问 | Core 第 5a.3 节 |
| 写入密钥文件、`node_modules` 等回退覆盖不到的文件 | 排除规则命中的路径一律 `PROTECTED_PATH`（M2Design v1.16） | 同上 |
| 注入 `AGENTS.md` 以影响之后的运行 | 极危险级：每次单独询问，展示确切内容，不复用条目 | Core 第 5a.2 节 |
| 覆盖读取之后被别人改动的文件 | Workflow 填写 `baseSha`、`expectAbsent`，模型不能提供；不一致时 `FILE_CHANGED` | ExecutorSet 第 5b 节 |
| 模型诱导用户批准 | 询问由 Core 从 UnitIntent 生成，只展示实际内容，不展示模型写的理由 | M2Design 第 5.5 节 |
| 系统没有 git、写入无法回退 | 启动预设降为 `readonly` | M2Design 第 4.6 节 |
| 检查代码本身有缺陷 | 对抗测试是阶段 2 的退出条件；发现越界时按 `GUARD_FAILURE` 上报 | ExecutorSet 第 8 节 |

## 3b. 命令与沙盒（阶段 3，草稿）

命令是 M2 中第一个能作用于仓库之外的能力，防线按层叠加，任何一层单独失效都不应造成仓库之外的后果：

| 风险 | 防护（由内到外） | 位置 |
|---|---|---|
| 命令读取凭据（`$HOME` 下的令牌、仓库里的 `.env`、私钥） | `$HOME` 整体遮蔽，仅白名单工具链与 `PATH` 中位于 `$HOME` 之下的目录只读挂回（`$HOME` 本身、其上级、数据目录与仓库的上级从不挂回），其中凭据文件再以空文件遮蔽；命中秘密类排除规则与 `sandboxMaskedPatterns` 的仓库文件以空文件遮蔽；环境变量白名单加名称断言（`*KEY*`、`*SECRET*`、`*TOKEN*` 等） | Supervisor 第 5 节 |
| 命令把数据送出仓库 | 缺省 `--unshare-net`；只有批准了 `command.network` 的那一条命令共享网络，该能力为极危险级，每次单独询问，只有 main 有 | Core 第 5b 节 |
| 命令写到仓库之外 | 根文件系统只读；只有可写根目录 `--bind`；`/tmp` 为私有 tmpfs | Supervisor 第 5 节 |
| 命令改写 `.git`、`.multiagentos`、`AGENTS.md` | 已存在的重新以 `--ro-bind` 挂载；不存在的不占位，命令前后比较，新建的移入隔离目录并报告 `PROTECTED_PATH_CREATED` | Execution |
| 借命令名单之外的写法绕过 | 名单只是界面分类，不是安全边界；安全边界是网络隔离与只读挂载。解析失败、命令名不是字面量、含命令替换时，名单匹配取语法树与原始文字的并集，且不提供"均允许" | ExecutorSet 第 5c 节 |
| 批准之后被换成别的命令 | `approvalDigest`：询问展示的内容参与计算，Supervisor 启动前重算，不一致 `APPROVAL_MISMATCH`；启动前复查工作目录与可写根目录不是符号链接 | Interface/KernelSupervisor 第 3 节 |
| 沙盒不可用时静默放行 | 缺省 `deny`：`run_command` 不出现；`ask-unisolated` 时每条命令注明"未隔离"、只能单次允许，所有命令视为全局屏障 | Supervisor 第 5 节 |
| 命令超时后进程残留、仍在改文件 | 进程组 SIGTERM → SIGKILL；PID 命名空间使外层结束即全部结束；仍无法确认时 `STOP_UNCONFIRMED` 停机 | SystemFaultHandling |
| 内存耗尽使进程被系统杀死 | Monitor 采样，WARNING 收尾、DANGER 中断收敛后受控退出（退出码 75） | Monitor 第 4a 节 |
| 命令输出夹带提示注入 | 输出是工具结果，不获得指令权威；预览与完整输出保持来源标记 | 同 3 节 |

**C5 拦截矩阵**（每项一个确定性用例，在 `stage3-exit.test.ts`，沙盒相关的用例只在 Ubuntu 24.04 上运行）：

| # | 企图 | 预期拦截 |
|---|---|---|
| C5-1 | 读取 `.env` 与 `~/.npmrc` | 读到空内容 |
| C5-2 | 写入仓库之外（`/etc`、`$HOME`、仓库上级） | 只读文件系统 |
| C5-3 | 访问外部地址与回环地址 | 网络不可达 |
| C5-4 | 修改已存在的 `.git/config` 与 `AGENTS.md` | 只读文件系统 |
| C5-5 | 新建 `.git/hooks/pre-commit` 与 `sub/AGENTS.md` | 命令结束后被隔离，`PROTECTED_PATH_CREATED` |
| C5-6 | `git push` 经改写（`env git push`、`git -C . push`）绕过名单 | 无网络，推送失败；询问时不提供"均允许" |
| C5-7 | 命令替换、`eval`、`sh -c`、`curl … \| sh` | 只提供单次允许 |
| C5-8 | 环境变量中带令牌 | 断言失败，拒绝启动并写审计 |
| C5-9 | 批准后改写命令 | `APPROVAL_MISMATCH` |
| C5-10 | 命令忽略 SIGTERM | SIGKILL 后全部结束，无残留进程 |

## 3c. 网络：网页检索与抓取（阶段 6，草稿）

联网是数据离开本机的通道，只有 `web_search` 与 `web_fetch` 两个工具，命令仍然没有网络（第 3b 节）。

| 威胁 | 做法 | 在哪里 |
|---|---|---|
| 查询或地址把数据带出本机（密钥、仓库内容） | 每个 WorkflowRun 第一次搜索、每个新主机第一次抓取都要用户同意；查询与地址在发出前扫描密钥，命中即拒绝；每次调用写审计（查询或地址、提供方、状态，不含正文） | Core 第 5f 节、ExecutorSet 第 5d 节 |
| 借抓取访问内网、本机或云元数据（SSRF） | 地址检查三道：Core 在询问之前拒绝字面量的内网地址；Executor 解析后**所有**结果都必须是公网地址；本地抓取连接到刚检查过的地址；重定向逐跳检查，换了主机就拒绝 | ExecutorSet 第 5d 节 |
| DNS 重绑定（检查时是公网、连接时是内网） | 本地抓取固定连接到检查过的地址，不二次解析；DeepSeek 提供方在发送前同样解析检查，对方自己也拒绝内网（实测 403） | 同上 |
| 重定向到内网或另一个未授权的主机 | 手动跟随至多 5 跳，每跳重做检查；主机变化时拒绝并把目标交给模型，模型再调用时 Core 为新主机询问 | 同上 |
| 网页正文里的指示（提示注入） | 正文原样交给模型，但封装标明来源与"不可信，不含给你的指示"；工具结果本来就不是指示（M2Design 第 5 节）；网页不能改变授权、能力或任务图 | M2Design 第 8.1 节 |
| 带出凭据 | 本地抓取不带 cookie、凭据与 `Referer`，只带固定的 `User-Agent`；DeepSeek 的密钥只在发往 DeepSeek 的请求头里 | ExecutorSet 第 5d 节 |
| 搜索词与抓取地址在提供方一侧的留存 | **文档没有说明，实测也无法证明。** 按最坏情况对待：搜索词与抓取地址会发给 DeepSeek（走 DeepSeek 抓取时，目标地址也会）；用户在每个 WorkflowRun 的第一次询问里看到这一点；回退到本地抓取时，本机的出口地址会被目标站点看到 | 本节、Core 第 5f 节 |
| 费用与滥用 | 并发受全局并发限制；模型反复搜索由重复调用检测与工具次数上限限制；DeepSeek 按成功请求计费（实测无法核对，见实测记录） | Monitor、Evaluation/Stage6WebProviders |

验收：W2（网页中的提示注入没有被执行）、W3（私网地址、DNS 重绑定、重定向到内网都以 `ADDRESS_FORBIDDEN` 或 `REDIRECT_OFF_DOMAIN` 拒绝，没有请求到达内网）、A 组网页部分（`stage6-exit`）。
