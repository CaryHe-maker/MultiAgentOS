# MultiAgentOS M2 安全

> 状态：草稿（阶段 1 的部分）。全文在阶段 3 的文档门中完成（M2Plan 第 6.4 节）。

## 1. 目的与范围

本文集中说明 M2 的威胁模型、各类风险由哪一层防护，以及验收 C5 的拦截矩阵。机制分散在各组件文档中，本文只做汇总与对应，
不重新定义机制；设计以 [M2Design](M2Design.md) 第 5、6、9.5 节为准。

## 2. 威胁模型（框架）

| 来源 | 假设 | 阶段 |
|---|---|---|
| 被分析仓库的内容（源码、文档、`AGENTS.md`、模板） | 可能来自他人，可能包含提示注入；不获得指令权威，除非用户按内容信任过 | 1 |
| 模型输出 | 只是提案；可能编造工具、越权、重复调用 | 1 |
| 网页内容 | 不可信；可能包含提示注入与指向内网的地址 | 6 |
| 命令 | 在沙盒中运行；可能试图联网、越出可写范围、读取凭据 | 3 |
| 用户 | 可信；但可能被诱导批准，因此授权询问只展示实际要执行的内容 | 1 |

## 3. 项目指令的信任（阶段 1）

| 风险 | 防护 | 位置 |
|---|---|---|
| 克隆来的仓库借 `AGENTS.md` 取得 system 级的指令权威 | 只有用户按 `(仓库, SHA)` 确认信任过的内容才进入 system 段；内容一变化就重新询问 | [Kernel/Core](Kernel/Core.md) 第 5.2 节 |
| 未被信任的 `AGENTS.md` 仍可能包含注入 | 以 user 角色、标明"仓库材料，未经用户信任"出现在历史开头；不进入 system 段 | [ExecutorSet](Library/ExecutorSet.md) 第 5.1 节 |
| `readonly` 预设下被诱导信任 | `readonly` 预设不询问，`AGENTS.md` 一律按未被信任处理 | Core 第 5.2 节 |
| 信任记录被当作授权 | 信任记录不授予任何执行能力，不是授权条目，也不是 Lease | M2Design 第 9.5 节 |
| Agent 修改 `AGENTS.md` | 只能经文件工具，按极危险级逐次询问；命令无法写入或新建（阶段 2、3） | M2Design 第 5.2、6.1 节 |
