# MultiAgentOS AgentToolPool

## 1. 定位

AgentToolPool 是模板类集合，用于描述 Agent、Unit、Tool 及其组合。
它提供可复用的行为组织方式，不是自主运行的目录服务，也不是 Executor 原子代码的第二份实现。

模板由 Workflow 和 Kernel 按职责使用。静态模板不拥有 AgentRun、Attempt、权限或资源账本。

## 2. 模板关系

| 概念 | 模板表达的内容 |
|---|---|
| Agent | 角色、目标处理方式、可用 Unit、行为约束与运行上限（如每次运行的轮次上限） |
| Unit | 一个操作单元、输入输出关系、执行组合与受保护能力声明 |
| Tool | 面向模型的可调用工具描述：名称、说明与参数结构；不决定授权 |
| Model / Prompt | 模型使用要求、提示组织与适用关系 |
| Executor 引用 | 将模板行为连接到 ExecutorSet 中的明确实现 |

Unit 连接一个或多个 Executor，并在定义中声明所需的受保护能力。
声明了受保护能力的 Unit 必须通过 Lease 审核；未声明的 Unit 使用开发者明确授予的权限。
受保护能力声明由可信模板确定，不允许模型通过改写请求绕过权限审核。
Unit 可以关联面向模型的 Tool 描述，但是否需要授权只看受保护能力声明。

模板规定可用组合，Kernel 决定本次请求是否可以执行。
受保护能力声明触发相应审核，不代表审核已经通过。
Agent 定义中的运行上限由 Workflow 读取并执行，Kernel 不解释这些业务上限。

## 3. 模板与原子代码

AgentToolPool 表达如何组织能力，ExecutorSet 提供具体原子软件行为。
模板中的 Executor 引用必须能对应到适用实现，不复制并维护另一套可漂移的执行代码。

共享结构和验证语义来自 SharedContracts。模板可以描述组合和使用约束，
但不能直接访问系统服务、修改运行状态或触发副作用来替代 Kernel 执行。

## 4. 版本与运行固定

已发布模板和引用具有可辨识的版本与完整性依据。
Workflow 固定本次运行采用的组合，Kernel 核对模板与代码是否匹配，
不能在运行中静默替换为当前默认版本。

模板停用或行为实现不再可信时，需要重新判断运行适用性；
保存历史版本不意味着继续允许执行。
模板更新、替代与迁移必须显式表达，不能通过任意扩展内容绕过契约。

## 5. 边界

AgentToolPool 不保存凭据、Lease、运行实例、动态预算或结果。
开发者授予权限的路径属于可信设计的一部分，不能由动态模型输出创造。
模板本身不决定部署位置、进程生命周期或业务结果是否成功。
