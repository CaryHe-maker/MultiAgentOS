# MultiAgentOS ExecutorSet

## 1. 定位

ExecutorSet 是具体 Executor 的原子软件行为代码集合。
它实现模型调用、文件操作、搜索、上下文处理及其他执行能力，由 Kernel.Execution 调用。
它不是独立 Module，不自行管理任务、调度、Lease 或跨运行状态。

“原子”指可组合的软件行为粒度，不保证效果不可中断、可回滚或可安全重复。

## 2. 与模板及运行时的关系

AgentToolPool 提供模板和组合，SharedContracts 提供公共契约，
ExecutorSet 提供行为实现，Kernel 管实际运行。

```text
模板声明行为组合 → Kernel 确认执行条件
  → Execution 调用 ExecutorSet 中的实现
  → 返回结果与效果事实 → Kernel 确认 → Workflow 验收
```

代码版本及其行为契约应能与模板引用对应；行为变化不能被相同名称掩盖。
Executor 的能力存在不等于调用者获准使用。含 Tool 的链由 Core 检查 Lease，
无 Tool 链依据可信开发者授权；Executor 无权改变这一区分。

## 3. 行为类别

| 类别 | 行为 |
|---|---|
| 模型 | 组织请求、接收输出与用量、表达外部调用失败 |
| 文件与搜索 | 受限读取、查找、定位和来源提取 |
| 上下文 | 概览、组装、压缩、去重、排序与预算裁剪 |
| 工作区与变更 | 受控修改、变更物化、集成操作和验证 |
| 外部服务 | 在声明范围内执行服务操作并报告效果 |

类别不规定固定 Executor 数量或类结构。原子行为可以组合，但不得绕过 Kernel
自由调用未获准能力或递归扩大业务工作。

## 4. 上下文能力

ContextEngine 不再作为独立运行模块，其能力由相应 Executor 实现。
概览帮助理解工作材料，检索定位证据，组装形成模型输入，压缩控制上下文规模。

必须保留的语义包括：

- 来源及适用版本可追踪，零结果不能用无关内容伪造召回。
- 输入中的指令、业务事实与外部不可信材料保持区分。
- 访问范围和数据失效约束贯穿检索与组装，不能因命中共享索引扩大可见性。
- 裁剪与摘要不得伪装为完整原文，模型生成结论不覆盖来源证据。
- 内容快照与元数据观察是不同概念，不能以元数据变化检测证明正文一致。
- 输出具有明确预算与丢弃信息，估算消耗不能当作实际计费用量。

检索台账、索引关联等长期运行状态归 Execution，正文归 ArtifactStore。
Executor 接收受控状态视图并返回计算结果，不在静态库建立全局可变记忆。
记忆的来源、适用范围、失效与删除传播必须明确，用户偏好和业务决定仍归相应 Owner。

## 5. 执行约束与效果

Executor 只使用本次获准的输入和资源，报告结果、消耗及已知或未知效果。
权限和 Lease 裁决不在各 Executor 中重复实现，原子代码不得读取 Core 的 Lease 内容。

模型回复中的工具提案交回业务流程，不直接作为任意执行命令。
运行取消或失败后仍需报告已发生效果，不能将异常统一解释为未执行。
不可信行为代码必须受实际隔离，不能因归入代码集合而获得内核管理权限。

## 6. 演进与验证

替换行为实现须保持其声明语义，或显式调整模板和契约。
验证关注输入输出、来源完整性、数据范围、重复执行条件、取消、未知效果与资源使用。
不同运行的状态不得通过库中的共享对象相互污染。
