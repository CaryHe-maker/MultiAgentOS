# findex 规格

一个本地全文检索工具：把 JSON Lines 文件里的文档建成磁盘上的索引，用一个小的查询语言检索，按 BM25 排序，给出摘要。只用 Python 3 标准库，不安装任何包。包名 `findex`，命令为 `python3 -m findex --index <索引目录> <子命令> ...`（索引目录不存在时创建）。

## 1. 文档与分析

- 输入文件每行一个 JSON 对象：`{"id": 字符串, "title": 字符串, "body": 字符串, "tags": [字符串, ...]}`。`id`、`title`、`body` 必须有且是字符串，`tags` 可省略（视为空列表），有则必须是字符串列表。
- **分词**：先转小写，再取所有连续的 `[a-z0-9]+` 片段为词。
- **停用词**（去掉，不占位置）：`a an and are as at be by for from in is it of on or the to with`。
- **词干**：对每个词按下列规则从上到下找第一条适用的，只用一条：
  1. 以 `sses` 结尾 → 去掉末尾的 `es`（classes → class）；
  2. 以 `ies` 结尾且长度大于 4 → 末尾 `ies` 换成 `y`（stories → story）；
  3. 以 `s` 结尾、不以 `ss` 结尾且长度大于 3 → 去掉 `s`（cats → cat）；
  4. 以 `ing` 结尾且长度大于 5 → 去掉 `ing`（jumping → jump）；
  5. 以 `ed` 结尾且长度大于 4 → 去掉 `ed`（jumped → jump）。
- 一篇文档的词序列是：标题的词序列，接着正文的词序列。词的位置按去掉停用词之后的顺序计。
- 标签不分词，只转小写。

## 2. 命令

所有错误：说明写到 stderr，退出码 2，索引不变。

- `add <文件>`：加入文件里的全部文档，打印 `added <N>`。索引里已有相同 id 的文档被新的替换。文件里任何一行不是合法 JSON 或不符合第 1 节，整个文件都不加入（退出码 2）。
- `delete <id> [<id> ...]`：删除这些文档，打印 `deleted <实际删除的个数>`；不存在的 id 忽略。删除后再 `add` 同一个 id，它重新出现。
- `search <查询> [--limit N] [--json]`：见第 3 节。
- `stats`：打印一行 JSON `{"docs": <现有文档数>, "terms": <现有文档的标题与正文中不同词的个数>, "segments": <段数>}`。
- `compact`：把所有段合并成一个，丢掉已删除和被替换的文档，打印 `segments 1`。合并前后任何查询的结果完全相同。

## 3. 查询

- 查询由空白分开的**子句**组成；单独的大写 `OR` 把查询分成几组。一篇文档匹配某组，当且仅当它满足这组的每一个子句；匹配查询，当且仅当它匹配任一组。
- 子句：
  - `词`：按第 1 节分析后得到的每个词，都出现在文档的标题或正文中。分析后为空（例如停用词）的子句忽略。
  - `"若干词"`（双引号）：分析后的词序列在文档的标题或正文中连续出现（位置相邻；标题与正文不跨接）。
  - `title:词`：分析后的词出现在标题中。
  - `tag:标签`：文档有这个标签（不区分大小写）。
  - `前缀*`：前缀转小写（不做词干），文档的标题或正文中有以它开头的词。
  - `-词`：分析后的词都不出现在标题与正文中。
- 每组至少要有一个不是 `-` 的有效子句；查询为空、某组没有有效的正向子句、双引号不成对，都是错误。
- **得分**（BM25，k1 = 1.2，b = 0.75）：
  - 文档长度 dl = 正文词数 + 2 × 标题词数；avgdl 为全部现有文档的 dl 平均值；N 为现有文档数。
  - 词 t 在文档中的频次 tf = 正文中出现次数 + 2 × 标题中出现次数；df 为含 t（标题或正文）的现有文档数；idf = ln(1 + (N − df + 0.5) / (df + 0.5))。
  - 一篇文档的得分是对**计分词**求和：idf × tf × (k1 + 1) / (tf + k1 × (1 − b + b × dl / avgdl))，只对在这篇文档中 tf > 0 的计分词求和。
  - 计分词：整个查询中 `词`、`"若干词"`、`title:词` 子句分析后的词，以及 `前缀*` 子句在这篇文档中匹配到的词；同一个词只计一次。`tag:` 与 `-词` 不计分。
- 结果按得分从高到低，得分相同按 id 升序；最多 `--limit` 条（缺省 10）。
- 文本输出：每条一行 `<id>\t<得分保留 4 位小数>\t<标题>`；没有结果时什么也不打印。
- `--json` 输出：`{"total": <匹配的文档总数>, "hits": [{"id", "score", "title", "snippet"}]}`，score 四舍五入到 4 位小数。
- **摘要** snippet：把正文按空白切成单词；第一个"分析后含有计分词（或以前缀子句开头的词）"的单词记为 i；取第 max(0, i−5) 个到第 i+5 个单词（含两端，不超出正文）；其中每个分析后含有这类词的单词写成 `[单词]`；单词之间用一个空格；开头不是正文第一个单词时前面加 `…`，结尾不是正文最后一个单词时后面加 `…`。正文中没有这样的单词时，取正文前 11 个单词（不加方括号）。

## 4. 存储与可靠性

- 每次 `add` 写一个新的**段**文件，段写好之后不再修改；`delete` 只记录删除。索引目录中的 `manifest.json` 记录哪些段与删除有效；索引目录里不被 `manifest.json` 引用的文件一律忽略。
- 写 `manifest.json` 必须原子：任何时刻中断，`manifest.json` 要么是旧的完整内容，要么是新的完整内容。
- 两个进程同时对同一个索引 `add`，两次都成功，两份文档都在。
- 5000 篇文档（每篇约 100 个词）一次 `add` 在 10 秒内完成；之后单个查询在 1 秒内返回。

## 5. 交付

- `tests/` 下至少 25 个单元测试，`python3 -m unittest discover -s tests -t .` 全部通过。
- `README.md`：用法与查询语言；`docs/design.md`：段与 manifest 的格式、删除与替换怎么生效、查询怎样求值与计分、并发与中断时的行为。
